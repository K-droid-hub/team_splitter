# 概要
コマンド入力者が入室しているボイスチャット内のメンバーを複数チームに分けます。任意のチャンネルで `/` を入力すればサジェストが出てくるため、コマンドと付随するオプションを選択してください。

# コマンド一覧
オプションは全て任意であり、デフォルトの値が設けられています。オプションを指定しない場合、デフォルトの値が使用されます。

| コマンド             | オプション                                | 備考                                                             |
| ---------------- | ------------------------------------ | -------------------------------------------------------------- |
| /チーム数で分ける        | チーム数 (デフォルト: 2)                      |                                                                |
| /1 チームあたりの人数で分ける | 人数 (デフォルト: 5)                        |                                                                |
| /人数分抽選           | 人数 (デフォルト: 5) / 優先者 ( "," 区切りで複数指定可) | ここで追加する優先者は固定されません。                                            |
| /一覧表示             | --                                   | 固定されていないメンバーは `次だけ〇〇` と表記されます。                                 |
| /観戦者登録           | 固定 (デフォルト: しない)                | 観戦者はチーム分けに含まれません。固定しない場合、次のチーム分けが終わった後、観戦者から自動で解除されます。         |
| /観戦者解除           | --                                    | 観戦者を解除します。同時に複数人指定はできません。                                      |
| /優先者登録           | 固定 (デフォルト: しない)                | 優先者は、人数分抽選に必ず選ばれるようになります。固定しない場合、次のチーム分けが終わった後、優先者から自動で解除されます。 |
| /優先者解除           | --                                   | 優先者を解除します。同時に複数人指定はできません。                                      |
| /リセット             | --                                   | 観戦者と優先者を全員解除します。                                               |
| /読み上げ開始           | 入退室通知 (デフォルト: しない)               | bot が実行者のボイスチャットに参加し、コマンドを打ったテキストチャンネルの発言を読み上げます。入退室通知を on にすると入退室も読み上げます。別のボイスチャットなら、同じサーバーでも別のテキストチャンネルを並行して読み上げられます。 |
| /読み上げ終了           | --                                   | 読み上げを終了します。音楽も流していなければボイスチャットから退出します。読み上げ対象以外のチャンネルで実行した場合は、自分のいるボイスチャットの読み上げを終了します。ボイスチャットが bot だけになると自動で退出します。 |
| /読み上げ声設定         | 話者 (必須)                            | あなたの発言を読み上げる声を選択します。未設定の人は既定の声で読み上げられます。 |
| /パネル               | --                                   | チャンネルに操作パネルを設置します。各コマンドをボタンから実行でき、スラッシュコマンドが苦手な人でも使えます。         |
| /パネル終了           | --                                   | このチャンネルのパネルを閉じます。設置上限に達したときは、どこかで閉じてから設置してください。         |

# 読み上げ機能
`/読み上げ開始` で bot がボイスチャットに参加し、VOICEVOX で発言を音声合成して読み上げます。音声合成には別途 VOICEVOX エンジンが必要です(下記「運用」参照)。

`/読み上げ声設定` で選んだ声は SQLite (`data/voices.db`) に保存され、コンテナをリビルド・再起動しても保持されます。Docker Compose では `voice_data` という named volume に載せているため、`docker compose up --build` で作り直しても設定は消えません。保存先は `.env` の `VOICE_DB_PATH`(既定 `data/voices.db`)で変更できます。

# 操作パネル
`/パネル` を実行すると、そのチャンネルにボタン付きの操作パネルが設置されます。各機能はボタンから実行でき、チーム数・人数・対象メンバーといった入力もその場に出るボタンから選ぶだけです(スラッシュコマンドを覚える必要はありません)。パネルは操作のたびに最新の状態でチャンネル最下部へ貼り直されます。VC の人数が多くてボタンに収まらない場合は、自動でセレクトメニューに切り替わります(1 メニュー 25 人ずつに分けて並べます)。

観戦者・優先者の登録は、サーバーとボイスチャンネルの組ごとに独立して保持されます。別のサーバーや同じサーバーの別 VC で操作しても、互いの登録は消えません。

## 設置数の上限
同時に設置できるパネルは **2 サーバー × 各サーバー 2 チャンネル** までです。上限に達した状態で `/パネル` を実行すると、今どのチャンネルで開いているかを添えて断られます。`/パネル終了` でどこかのパネルを閉じてから設置してください。

設置位置は SQLite (`data/panels.db`) に保存されるため、bot を再起動しても古いパネルを消してから貼り直せます(再起動のたびにパネルが増えることはありません)。保存先は `.env` の `PANEL_DB_PATH`(既定 `data/panels.db`)で変更でき、読み上げ声・意気込みと同じ `voice_data` volume に載っています。

`読み上げ声設定` ボタンからは自分の読み上げ声も変更できます(この設定は本人にだけ表示され、パネルの貼り直しは行いません)。開くと最初に **現在のあなたの声** が表示され、一覧では話者ごとに声質の短い説明が付くため、名前だけでは分かりにくい声も選びやすくなっています。今の声のボタンは緑で示され、`🔊試聴` で設定を変えずに聴き比べできます。

`意気込み設定` ボタンを押すと入力モーダルが開き、自分の意気込みを書けます。設定した意気込みは、チーム分け・人数分抽選・一覧表示で名前の下に小さめの文字で表示されます(未設定の人は名前だけが表示されます)。意気込みはサーバー(Discord ギルド)ごとに独立して保持されるため、同じ人でもサーバーが違えば別々に設定できます。意気込みは SQLite (`data/aspirations.db`) に保存され、bot を再起動しても保持されます。保存先は `.env` の `ASPIRATION_DB_PATH`(既定 `data/aspirations.db`)で変更できます。読み上げ声設定と同じ `voice_data` volume に載せているため、`docker compose up --build` で作り直しても消えません。

# 音楽再生
YouTube などの URL や検索語を渡すと、ボイスチャットで音声を再生します。スラッシュコマンドではなく `!` 付きの隠しコマンドで、スラッシュコマンドの一覧には出てきません。

| コマンド | 備考 |
| ---- | ---- |
| `!play <URL または検索語>` | 実行者のボイスチャットに参加して再生します。再生中なら順番待ちのキューに追加します。URL ではない入力は検索語として扱い、先頭 1 件を再生します。 |
| `!skip` | 再生中の曲を飛ばして次へ進みます。 |
| `!stop` | 音楽を終了します。読み上げも使っていなければボイスチャットから退出します。 |
| `!queue` | 再生中の曲と順番待ちの一覧を表示します。 |

## 使える人の制限
`!play` などは `.env` の `MUSIC_ALLOWED_USER_IDS` に書いたユーザーだけが使えます(カンマ区切りで複数指定可)。許可されていない人が打っても**何も返さず黙って無視**します。隠しコマンドなので、存在を悟られないようにするためです。

`MUSIC_ALLOWED_USER_IDS` が未設定のときは**誰も使えません**。未設定を「全員許可」に倒すと事故につながるためです。ユーザー ID は Discord の開発者モードを有効にして、ユーザーを右クリック →「ユーザー ID をコピー」で取得できます。

## 読み上げと音楽は同じチャンネルで同時に使える
1 つのボイスチャットの中で、読み上げと音楽を同時に使えます。bot は 1 体だけ入り、読み上げが鳴っている間は音楽の音量を自動で下げます(言葉が音楽に埋もれないようにするためです)。喋り終わると元の音量に戻ります。

音楽の取得が回線の都合で一時的に詰まっても、読み上げは遅れずに聞こえます。

## 同時に使えるボイスチャンネル数
Discord は **bot アカウント 1 つにつき 1 サーバー 1 ボイス接続**までしか張れません。そのため、同じサーバーで 2 つのボイスチャットを同時に使いたいときのために、2 体目の bot を用意できます。

- メイン bot: 全コマンドと発言の読み取りを担当します
- 2 体目の bot: 声を貸すだけで、コマンドも発言の読み取りも行いません

2 体とも招待したサーバーでは **同時 2 ボイスチャンネル**、メイン bot だけを招待したサーバーでは **1 ボイスチャンネル**まで使えます。どちらのチャンネルでも、読み上げと音楽を同時に使えます。接続上限はサーバー単位なので、別のサーバーと枠を取り合うことはありません。

bot は次の順で割り当てます。

1. 実行者のボイスチャットにすでに bot がいれば、その bot を使う(2 体が同じチャンネルに並ぶことはありません)
2. いなければ、メイン bot → 2 体目の順で空いている bot を使う
3. どちらも埋まっていれば、どのチャンネルで使用中かを添えて断る

普段はメイン bot だけが見え、2 体目は 2 つ目のボイスチャットを使うときにだけ入ってきます。

`PLAYER_BOT_TOKEN` が未設定のときは、2 体目なしで動きます。この場合はどのサーバーも 1 ボイスチャンネルまでになります(そのチャンネルの中では、読み上げと音楽を同時に使えます)。

## 自動終了
キューが空になってから 60 秒が経つと、音楽を終了します。読み上げも使っていなければ、ボイスチャットから退出して接続の枠を返します。放置で枠が埋まり続けないようにするためです。ボイスチャットが bot だけになったときも同様に終了します。

## 注意点
- 音源の取得には `yt-dlp` を使っています。YouTube 側の仕様変更で突然動かなくなることがあるため、`requirements.txt` ではバージョンを固定していません。再生に失敗するようになったら `docker compose up --build` でイメージを作り直してください。
- YouTube の利用規約では、動画のダウンロードや再配信は本来認められていません。身内のサーバーで使う前提の機能ですが、規約違反になり得ることは認識した上で利用してください。
- 音楽を流しているボイス接続 1 本につき ffmpeg プロセスが 1 つ動きます。読み上げと音楽の合成は bot のプロセス内で行い、Intel N95 での実測は 1 接続あたり 1 コアの約 3% でした。負荷で効いてくるのは、むしろ VOICEVOX の音声合成のほうです。

# Bot 権限

## 一般権限
- チャンネルを表示

## テキストの権限
- メッセージを送る
- リンクを埋め込み

## 音声の権限
- 接続
- 発言

## Gateway Intent(Developer Portal 側)
上記のインストール権限とは別に、以下の Privileged Gateway Intents を有効にしてください。読み上げ機能で発言内容を取得するために必要です。
- Message Content Intent
- Server Members Intent

## 2 体目の bot の権限
2 体目の bot は声を貸すだけなので、必要な権限が少なくて済みます。

- 招待時のスコープ: `bot` のみ(コマンドを登録しないため `applications.commands` は不要)
- 権限: 接続 / 発言
- Privileged Gateway Intents: **不要**(発言内容もメンバー一覧も使いません)

2 つのボイスチャットを同時に使いたいサーバーにだけ招待してください。意図的にメイン bot だけにしているサーバーがあっても問題ありません。起動時のログに `ℹ️ 2 体目の bot がいないサーバー(1 チャンネルで動作)` として一覧が出るので、招待し忘れはここで確認できます。

# 運用
`.env-template` のファイル名を `.env` に修正し、DISCORD_TOKEN と GUILD_IDS を入力してください。特定のグループでしか動作しない仕様になっています。

音楽再生を使う場合は、あわせて以下も入力してください。どちらも未設定でも bot は起動します(音楽機能だけが使えない状態になります)。

- `PLAYER_BOT_TOKEN`: 2 体目の bot のトークン(Developer Portal でアプリをもう 1 つ登録して取得)。未設定なら 1 体で動き、どのサーバーも 1 ボイスチャンネルまでになります
- `MUSIC_ALLOWED_USER_IDS`: `!play` を使えるユーザー ID(カンマ区切り)。未設定だと誰も使えません

## 読み上げのための追加準備
読み上げ機能には VOICEVOX エンジンと ffmpeg、libopus が必要です。libopus は読み上げと音楽を合成した音声を Discord 向けに変換するのに使います。

- Discord は 2026-03-02 に voice の DAVE(E2E 暗号化)を必須化したため、bot が voice に参加するには DAVE 対応版の discord.py(2.7 以降)と `davey` パッケージが必要です。どちらも `requirements.txt` に含めています(未対応版では close code 4017 で接続拒否されます)。
- `.env` の `VOICEVOX_URL`(既定 `http://voicevox:50021`)で VOICEVOX エンジンの接続先を、`VOICEVOX_SPEAKER`(既定 `3`)で既定話者を指定します。
- Docker Compose で起動する場合、`voicevox` サービスが自動で立ち上がり、ffmpeg も bot イメージに同梱されます。追加の準備は不要です。
- ローカルで直接実行する場合は、別途以下が必要です。
  - VOICEVOX エンジン: `docker run --rm -p 50021:50021 voicevox/voicevox_engine:cpu-latest`
  - ffmpeg と libopus: `brew install ffmpeg opus`(macOS の場合)
  - Python 依存: `pip install -r requirements.txt`(PyNaCl・davey を含む)
  - このとき `.env` の `VOICEVOX_URL` は `http://localhost:50021` にしてください。
