# 概要
コマンド入力者が入っているボイスチャットのメンバーを、複数チームに分けます。`/` を入力すると候補が出ます。

# コマンド一覧
オプションは任意です。省略するとデフォルト値を使います。

| コマンド | オプション | 備考 |
| --- | --- | --- |
| /チーム数で分ける | チーム数 (2) | |
| /1 チームあたりの人数で分ける | 人数 (5) | |
| /人数分抽選 | 人数 (5) / 優先者 (カンマ区切り) | 追加した優先者は固定されません |
| /一覧表示 | -- | 固定されていないメンバーは `次だけ〇〇` と表示 |
| /観戦者登録 | 固定 (しない) | チーム分けの対象外。固定しなければ次のチーム分け後に解除 |
| /観戦者解除 | -- | 同時に複数人は指定できません |
| /優先者登録 | 固定 (しない) | 人数分抽選で必ず選ばれます。固定しなければ次のチーム分け後に解除 |
| /優先者解除 | -- | 同時に複数人は指定できません |
| /リセット | -- | 観戦者と優先者を全員解除 |
| /読み上げ開始 | 入退室通知 (しない) | 実行者の VC に参加し、このチャンネルの発言を読み上げ |
| /読み上げ終了 | -- | 読み上げを終了。音楽も流していなければ退出 |
| /読み上げ声設定 | 話者 (必須) | 自分の発言を読み上げる声。未設定は既定の声 |
| /パネル | -- | ボタン操作のパネルを設置 |
| /パネル終了 | -- | このチャンネルのパネルを閉じる |

# 操作パネル
`/パネル` でボタン操作のパネルを設置します。コマンドを覚えなくても、全機能をボタンから使えます。

- 操作のたびにパネルを最下部へ貼り直します。結果は公開で表示されます。
- bot の投稿は通知が鳴らないよう送っています。VC にいない人の端末が鳴らないようにするためです。
- 人数が多くてボタンに収まらないときは、セレクトメニューに切り替わります(25 人ずつ)。
- 入退室通知の ON/OFF もパネルから切り替えられます。設定はチャンネルごとに保持されます。
- 観戦者・優先者の登録は、サーバーと VC の組ごとに保持されます。
- 設置上限は **2 サーバー × 各 2 チャンネル**です。上限に達したら `/パネル終了` で閉じてください。
- 読み上げ声設定と意気込み設定は本人にだけ表示されます。声は `🔊試聴` で聴き比べできます。意気込みはチーム分けなどの一覧に名前の下に出ます(サーバーごとに別々に設定)。

# 読み上げ
- 発言を VOICEVOX で読み上げます。VOICEVOX エンジンは別途必要です(下記「運用」参照)。
- 読み上げと音楽は同じ VC で同時に使えます。読み上げ中は音楽の音量を自動で下げ、喋り終わると戻します。
- 声の設定・意気込み・パネルの位置は SQLite に保存され、再起動やリビルドでも残ります。保存先は `.env` の `VOICE_DB_PATH` / `ASPIRATION_DB_PATH` / `PANEL_DB_PATH` で変更できます(既定は `data/`)。

# 音楽再生
URL か検索語を渡すと、VC で音声を再生します。`!` 付きの隠しコマンドなので、スラッシュコマンドの一覧には出ません。VC に入っている人なら誰でも使えます。操作は自分がいる VC の再生だけに効きます。

| コマンド | 内容 |
| --- | --- |
| `!play <URL または検索語>` | 再生します。再生中ならキューに追加します |
| `!skip` | 今の曲を飛ばします(ループも解除されます) |
| `!stop` | 音楽を終了し、キューも全部消します。読み上げも使っていなければ退出します |
| `!repeat` | 今の曲をキューの先頭に入れ、次にもう一度流します |
| `!loop` | 今の曲を繰り返します。もう一度実行すると解除されます |
| `!queue` | 再生中の曲と順番待ちを表示します |
| `!volume <1〜100>` | 音楽の音量を 1〜100 の目盛りで設定します(100 が最大音量の 50%、既定は 50)。省略すると今の音量を表示します |

- キューが 60 秒空になると、音楽を終了します。
- キューの上限は 100 件です。

# 同時に使える VC 数
Discord は bot 1 体につき、1 サーバーで 1 つの VC にしか接続できません。2 体目の bot(`PLAYER_BOT_TOKEN`)を入れると、同じサーバーで **2 つの VC を同時に**使えます。

- 2 体目は声を貸すだけです。コマンドも発言の読み取りも行いません。
- 割り当ては次の順です。実行者の VC に bot がいればそれを使い、いなければメイン bot → 2 体目の順で空いている bot を使います。どちらも埋まっていれば、使用中の VC を添えて断ります。
- 2 体目は、2 つ目の VC を使うときにだけ入ります。
- 2 体目を招待していないサーバーは 1 VC までです。招待忘れは起動ログの `ℹ️ 2 体目の bot がいないサーバー` で確認できます。

# 注意点
- 音源の取得には `yt-dlp` を使います。YouTube 側の変更で動かなくなったら、`docker compose up --build` でイメージを作り直してください(バージョンは固定していません)。
- YouTube の利用規約では、動画のダウンロードや再配信は認められていません。身内のサーバー前提の機能ですが、規約違反になり得ることを理解した上で使ってください。
- 音楽を流している VC 1 本につき ffmpeg が 1 つ動きます。負荷は主に VOICEVOX の音声合成側です(Intel N95 で、1 接続あたり 1 コアの約 3%)。
- 使える人の制限はありません。bot は信頼できるメンバーだけのサーバーに入れてください。

# Bot 権限

## 招待時のスコープ
- `bot`
- `applications.commands`(スラッシュコマンドの登録に必要)

## 権限
- 一般: チャンネルを表示
- テキスト: メッセージを送る、リンクを埋め込み
- 音声: 接続、発言

## Gateway Intent(Developer Portal)
読み上げで発言内容を取得するため、次の Privileged Gateway Intents を有効にしてください。
- Message Content Intent
- Server Members Intent

## 2 体目の bot
- 招待スコープ: `bot` のみ(コマンドを登録しないので `applications.commands` は不要)
- 権限: 接続、発言
- Privileged Gateway Intents: 不要
- 2 つの VC を同時に使いたいサーバーにだけ招待してください。

# 運用
1. `.env-template` を `.env` にコピーし、`DISCORD_TOKEN` と `GUILD_IDS` を入力します。`GUILD_IDS` に書いたサーバーでだけ動きます。
2. 音楽を使う、または 2 体目を使う場合は `PLAYER_BOT_TOKEN` も入力します。未設定でも起動し、その場合は音楽・2 体目が使えないだけです。
3. 読み上げには VOICEVOX が必要です。`VOICEVOX_URL`(既定 `http://voicevox:50021`)と `VOICEVOX_SPEAKER`(既定 `3`)で接続先と既定話者を指定します。

Docker Compose で起動すると、VOICEVOX と ffmpeg は自動で用意されます。ローカルで直接動かす場合は次が必要です。
- VOICEVOX: `docker run --rm -p 50021:50021 voicevox/voicevox_engine:cpu-latest`(`VOICEVOX_URL` は `http://localhost:50021` に変更)
- ffmpeg と libopus(macOS なら `brew install ffmpeg opus`)
- Python 依存: `pip install -r requirements.txt`

Discord は voice の DAVE(E2E 暗号化)を必須にしています。そのため、discord.py 2.7 以降と `davey` が必要です(どちらも `requirements.txt` に含めています)。未対応の版では、close code 4017 で接続が拒否されます。
